# Phase 11 — SEO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add technical and on-page SEO to the existing ArtNiyyətli public site (localized titles/descriptions, canonical URLs, Open Graph/Twitter metadata, `robots.txt`, `sitemap.xml`, justified JSON-LD, correct indexability, meaningful image alt text) without changing the Laravel + React SPA architecture, the public API contract, or the database schema beyond wiring up schema that already exists.

**Architecture:** A server-side `PublicPageSeoResolver` (new, Laravel-only) mirrors the client-side router's route table and, for any given path + locale, resolves one `PageSeo` value object by querying the *same* Eloquent models the public API already queries (no new API endpoints). `routes/web.php`'s two SPA-shell routes call this resolver and inject the result into `public.blade.php`'s `<head>` (title, meta description, canonical, robots, Open Graph, Twitter, JSON-LD) *before* any JavaScript runs — this is what makes the metadata visible to crawlers and social-media link previews, which do not reliably execute the SPA's JavaScript. Because switching pages inside the SPA never triggers a fresh server request, a small hand-rolled `usePageMeta` hook (no new dependency) updates `document.title` and the same meta tags client-side on every in-app navigation, so real users' browser tabs and any client-visible state stay correct too. `robots.txt` and `sitemap.xml` are dynamic Laravel routes built from live, already-scoped Eloquent queries (`is_active`, `published`, non-soft-deleted) — never static files, so they can never drift from what the site actually serves and never need production-only configuration to build a correct absolute URL (`config('app.url')` handles that in every environment).

**Tech Stack:** Laravel 13/PHP 8.4 (unchanged), React 19 (unchanged), zero new npm/Composer dependencies, Vitest + PHPUnit (existing toolchains).

**Spec:** `work-files/art-niyyetli-phase-11-seo.md`

## Global Constraints

- Preserve the existing Laravel + React public frontend architecture exactly — no SSR, no new routing library, no new meta-tag library (e.g. no `react-helmet`), no new PHP package.
- No public API contract changes and no new API endpoints — the SEO resolver queries Eloquent models directly, server-side, the same way the existing `Api\V1\*` controllers do; it is not itself part of `/api/v1`.
- No database schema changes. `seo_metadata` (polymorphic, per-entity-per-locale `title`/`description`/`og_image_id`) already exists (migrated in Phase 02, verified live: `database/migrations/2026_09_16_000036_create_seo_metadata_table.php`, model at `app/Models/SeoMetadata.php`) but is not yet used anywhere — this phase wires it up as an *optional override* layer, it does not add new columns/tables.
- Reuse existing services/utilities wherever they already do the exact thing needed: `App\Support\Api\LocaleResolver` for locale resolution, `App\Support\Api\LocalizedFields` for the field-level AZ/EN fallback, `App\Http\Resources\Api\Concerns\ResolvesMediaUrl` for image-variant URL building, `App\Services\Admin\SiteSettingService` for contact info. Do not reimplement any of these.
- No hardcoded `localhost` anywhere in canonical/OG/sitemap/robots output — always build absolute URLs from `config('app.url')`, which is already `http://localhost:8080` locally and would be the real domain in production, needing no code change between environments.
- Never invent SEO copy. Titles/descriptions are always either the entity's own already-authored content (via the existing per-field AZ/EN fallback) or, for the four list pages which have no single "entity" to describe, a live-data-derived count sentence (e.g. "12 artworks") — never static marketing copy invented for this phase. If a detail entity has no authored summary field at all, the meta description is omitted, not synthesized.
- Every indexability/eligibility rule reuses the exact same `is_active`/`status`/`published_at` visibility rule the corresponding public API controller already enforces — "eligible for SEO" always means "eligible for the public API," never a separately invented definition.
- No admin UI is added for editing `SeoMetadata` rows in this phase — reading/consuming the override table is in scope, building a screen to edit it is not (not requested by the spec's scope or Definition of Done; flagged as a follow-up in the final documentation task).
- Do not modify `work-files/art-niyyetli-phase-11-seo.md` (the spec) or anything else under `work-files/`. The spec's own §22 would permit one new reference doc there for the final Phase 11 documentation, but this plan places that deliverable at `docs/superpowers/specs/2026-09-18-phase-11-seo-implementation-notes.md` instead (Task 21) so the plan holds under the stricter constraint of never touching `work-files/` at all.
- Every task ends with passing tests; the final task additionally re-runs the *entire* existing PHPUnit and Vitest suites plus a production `npm run build`, confirming zero regressions anywhere in admin, public, or backend code.

## Architectural decisions this plan makes (read before starting)

These are the judgment calls the spec deliberately leaves to "the implementation plan" (§19, §22). Each is justified against the actual codebase, not invented preference.

1. **The SPA/crawler problem is solved by server-side metadata injection into the existing Blade shell, not SSR.** `routes/web.php`'s `/` and catch-all `/{any}` routes already return `view('public')` for every public path (verified: `resources/views/public.blade.php` is a single static shell today — `<title>ArtNiyyətli</title>` never changes). This plan makes that Blade render dynamic per-request: it resolves the requested path server-side (mirroring `resources/js/public/lib/useRouter.js`'s own `ROUTES` table) and queries the database *directly* — the same way `App\Http\Controllers\Api\V1\ArtworkController` etc. already do — to build real, complete `<head>` metadata before the response is sent. No React component is ever rendered on the server; only the static `<head>` tags are computed in PHP. This is the smallest change that makes crawlers and social-link-preview bots (which generally do not execute JavaScript) see correct, entity-specific metadata on a hard load of e.g. `/artworks/AN-2026-014`.
2. **A parallel, small client-side hook (`usePageMeta`) keeps in-app navigation correct too.** Since the SPA never reloads between pages, the server-injected tags from decision 1 stay frozen at whatever the *first* page was once the user starts clicking around client-side. `usePageMeta(seo)` — hand-rolled DOM manipulation, no dependency — updates `document.title` and the same meta tags on each page's own mount/data-change, using the exact data that page already fetched from the public API. This intentionally duplicates a small amount of "how do I build a title from this entity" logic between PHP (Task 5-9) and JS (Task 13-18); that duplication is an accepted, documented cost of not introducing SSR (see the final documentation task, Task 21).
3. **Server-rendered metadata always assumes the default locale (`az`) unless `?locale=` is present on the request.** The user's locale preference lives in `localStorage` (`resources/js/public/i18n/LocaleContext.jsx`), which the server cannot read on the very first request — there is no locale cookie and this plan does not add one (that would be a real architecture change, out of scope). This mirrors the public API's own default (`App\Support\Api\LocaleResolver::resolve()` already falls back to `az` for a missing/invalid `locale` value) — no new default is invented. This is documented as a known, accepted limitation, not fixed with new cross-cutting mechanism.
4. **Catalogue/exhibitions/articles filters and pagination are not currently reflected in the URL at all.** Verified in the actual code: `CataloguePage.jsx`'s `filters`/`page`, `ExhibitionsPage.jsx`'s `filter`/`page`, and `ArticlesPage.jsx`'s `page` are all plain `useState`, never written to `window.location`. There is therefore only one URL for each of these pages today (`/artworks`, `/exhibitions`, `/articles`) — no filter-combination-explosion problem exists yet to solve. The resolver still defensively ignores any query string on these paths (canonical always points at the bare path, indexable, `index,follow`) so that an externally-constructed URL with tracking/filter query parameters (e.g. `?utm_source=...`) never produces a different canonical or a duplicate-content signal.
5. **List pages (catalogue/artists/exhibitions/articles) get a live-count meta description, not invented copy.** These pages have no single "entity" to summarize. Rather than writing static marketing sentences, their description is generated from a live `count()` query already shaped like `App\Http\Controllers\Api\V1\HomepageController`'s existing `stats` block (e.g. "Explore a catalogue of 12 artworks.") — genuinely page-specific, live data, not fabricated.
6. **Detail-page descriptions always come from one specific, real, existing authored field — never several fields stitched together.** Artwork → `short_description`; Artist → `biography`; Exhibition → `short_text`; Article → `short_text`; static Page → `content` (truncated, since pages have no separate short field). If that field is empty for a given entity, the meta description tag is omitted entirely rather than synthesized from other fields — this is a deliberate, uniform rule so no task has to invent a one-off description-building heuristic.
7. **`og:type` stays `website` for every page except article details, which use `article`.** Open Graph's `product` type requires declaring an XML namespace on `<html>` and isn't otherwise supported anywhere in this codebase; adding it would be new surface area for one field. `article` is a core, always-valid Open Graph type and directly matches the spec's own suggested `Article` JSON-LD type, so treating articles specially (and nothing else) is the most conservative correct choice.
8. **JSON-LD is added only where the spec's own suggested type list maps cleanly onto real, loaded data**, and is intentionally *not* added to: the catalogue list page (no single-entity type fits a list), the exhibitions detail page beyond a breadcrumb, and static pages (no suggested type fits a generic informational page). Where used: `WebSite` + `Organization` (home), `VisualArtwork` + `BreadcrumbList` (artwork detail), `Person` + `BreadcrumbList` (artist detail), `Article` + `BreadcrumbList` (article detail), `BreadcrumbList` only (exhibition detail). **This was reviewed and confirmed as final** (not deferred): schema.org's `Event` type isn't in the spec's suggested list, exhibitions have no ticketing/attendance-mode/offer data that would make an `Event` markup meaningful, and adding it would be exactly the "invent data/scope" the spec warns against. `BreadcrumbList` is used everywhere it's appropriate (every detail page); no `Event` type is introduced anywhere in this phase, and none should be added later without a documented schema requirement — a concrete need this project doesn't currently have (e.g. ticket sales, structured start/end times surfaced to search results) that would justify the added complexity.
9. **The `SeoMetadata` override table is consulted, per entity per locale, before falling back to derived content.** It already exists, is already tested (`tests/Feature/Schema/SeoMetadataSchemaTest.php`), and was purpose-built in Phase 02 for exactly this ("Create reusable polymorphic SEO metadata" — `work-files/art-niyyetli-phase-02-database-schema.md`). Task 1 adds a `seoMetadata()` relation + a `seoOverride(Locale $locale): ?SeoMetadata` lookup to the five content models; every resolver task after it checks the override first. No admin UI to *write* these rows is built in this phase (see Global Constraints) — an admin can currently only populate them via `php artisan tinker`, which is an accepted, documented limitation, not a blocker to shipping the read side.
10. **`resources/js/admin/` is touched exactly once, for one line** — an admin-shell `<meta name="robots" content="noindex, nofollow">` tag (Task 10), which is a pure SEO/indexability requirement (spec §10: "admin/auth routes" must not be indexable) and touches no admin logic, screen, or test. No other admin file is touched anywhere in this plan.

<?php

namespace App\Support\Seo\Concerns;

use App\Enums\Locale;
use App\Models\SeoMetadata;
use Illuminate\Database\Eloquent\Relations\MorphMany;

trait HasSeoOverride
{
    public function seoMetadata(): MorphMany
    {
        return $this->morphMany(SeoMetadata::class, 'seoable');
    }

    public function seoOverride(Locale $locale): ?SeoMetadata
    {
        if ($this->relationLoaded('seoMetadata')) {
            return $this->seoMetadata->firstWhere('locale', $locale);
        }

        return $this->seoMetadata()->where('locale', $locale)->first();
    }
}
```

// app/Support/Seo/SeoText.php
<?php

namespace App\Support\Seo;

use App\Enums\Locale;
use Illuminate\Support\Str;

class SeoText
{
    public const SITE_NAME = 'ArtNiyyətli';

    public static function pageTitle(?string $entityTitle): string
    {
        $entityTitle = trim((string) $entityTitle);

        return $entityTitle === '' ? self::SITE_NAME : "{$entityTitle} — ".self::SITE_NAME;
    }

    public static function description(?string $text, int $limit = 160): ?string
    {
        $clean = trim(strip_tags((string) $text));

        return $clean === '' ? null : Str::limit($clean, $limit);
    }

    public static function absoluteUrl(string $path): string
    {
        $base = rtrim((string) config('app.url'), '/');
        $path = ltrim($path, '/');

        return $path === '' ? "{$base}/" : "{$base}/{$path}";
    }

    public static function ogLocale(Locale $locale): string
    {
        return match ($locale) {
            Locale::Az => 'az_AZ',
            Locale::En => 'en_US',
        };
    }
}
```

// app/Services/Seo/PublicPageSeoResolver.php
<?php

namespace App\Services\Seo;

use App\Enums\Locale;
use App\Enums\PageType;
use App\Http\Resources\Api\Concerns\ResolvesMediaUrl;
use App\Models\Artwork;
use App\Models\Page;
use App\Models\PageTranslation;
use App\Services\Admin\SiteSettingService;
use App\Support\Api\LocalizedFields;
use App\Support\Seo\PageSeo;
use App\Support\Seo\SeoLabels;
use App\Support\Seo\SeoText;

class PublicPageSeoResolver
{
    use ResolvesMediaUrl;

    public function __construct(private SiteSettingService $siteSettings) {}

    public function resolve(array $segments, Locale $locale): PageSeo
    {
        return match (true) {
            $segments === [] => $this->home($locale),
            count($segments) === 1 => $this->staticPage($segments[0], $locale),
            default => $this->notFound($locale),
        };
    }

    private function home(Locale $locale): PageSeo
    {
        $canonical = SeoText::absoluteUrl('/');

        $home = Page::query()
            ->where('type', PageType::Home)
            ->where('is_active', true)
            ->with(['sections' => fn ($q) => $q->where('is_active', true)->orderBy('sort_order'), 'sections.translations'])
            ->first();

        $hero = $home?->sections->first();
        $heroFields = $hero ? LocalizedFields::resolve($hero->translations, $locale, ['heading', 'body']) : ['heading' => null, 'body' => null];

        // The hero heading is itself the site's brand statement (e.g. "ArtNiyyətli"),
        // so unlike every other page's title this is used as-is rather than through
        // SeoText::pageTitle(), which would double-append the site name.
        $heading = trim((string) $heroFields['heading']);
        $title = $heading === '' ? SeoText::SITE_NAME : $heading;
        $description = SeoText::description($heroFields['body']);
        $ogImageUrl = $this->firstFeaturedArtworkImageUrl();
        $settings = $this->siteSettings->all();

        return new PageSeo(
            title: $title,
            description: $description,
            canonicalUrl: $canonical,
            index: true,
            follow: true,
            ogType: 'website',
            ogImageUrl: $ogImageUrl,
            ogLocale: SeoText::ogLocale($locale),
            jsonLd: [
                '@context' => 'https://schema.org',
                '@graph' => array_values(array_filter([
                    ['@type' => 'WebSite', 'name' => SeoText::SITE_NAME, 'url' => $canonical],
                    array_filter([
                        '@type' => 'Organization',
                        'name' => SeoText::SITE_NAME,
                        'url' => $canonical,
                        'email' => $settings['contact_email'] ?? null,
                        'telephone' => $settings['phone'] ?? null,
                    ]),
                ])),
            ],
        );
    }

    private function staticPage(string $slug, Locale $locale): PageSeo
    {
        $translation = PageTranslation::query()->where('slug', $slug)->first();
        $page = $translation
            ? Page::query()->where('id', $translation->page_id)->where('is_active', true)->with('translations')->first()
            : null;

        if (! $page) {
            return $this->notFound($locale);
        }

        $fields = LocalizedFields::resolve($page->translations, $locale, ['title', 'content']);
        $override = $page->seoOverride($locale);

        return new PageSeo(
            title: SeoText::pageTitle($override?->title ?? $fields['title']),
            description: SeoText::description($override?->description ?? $fields['content']),
            canonicalUrl: SeoText::absoluteUrl("/{$slug}"),
            index: true,
            follow: true,
            ogType: 'website',
            ogImageUrl: null,
            ogLocale: SeoText::ogLocale($locale),
            jsonLd: null,
        );
    }

    private function notFound(Locale $locale): PageSeo
    {
        return new PageSeo(
            title: SeoText::pageTitle(null),
            description: null,
            canonicalUrl: SeoText::absoluteUrl('/'),
            index: false,
            follow: true,
            ogType: 'website',
            ogImageUrl: null,
            ogLocale: SeoText::ogLocale($locale),
            jsonLd: null,
            httpStatus: 404,
        );
    }

    private function firstFeaturedArtworkImageUrl(): ?string
    {
        $artwork = Artwork::query()
            ->where('is_active', true)
            ->where('featured', true)
            ->orderBy('sort_order')
            ->with(['images' => fn ($q) => $q->where('is_main', true), 'images.media.variants'])
            ->first();

        $mainImage = $artwork?->images->first();

        return $mainImage ? $this->mediaVariantUrl($mainImage->media, 'catalogue') : null;
    }
}

// app/Http/Controllers/SitemapController.php
<?php

namespace App\Http\Controllers;

use App\Enums\ArticleStatus;
use App\Enums\PageType;
use App\Models\Article;
use App\Models\Artist;
use App\Models\Artwork;
use App\Models\Exhibition;
use App\Models\Page;
use App\Support\Seo\SeoText;
use Illuminate\Http\Response;

class SitemapController extends Controller
{
    public function index(): Response
    {
        $urls = array_merge(
            [['loc' => SeoText::absoluteUrl('/'), 'lastmod' => null]],
            $this->staticPages(),
            $this->artworks(),
            $this->artists(),
            $this->exhibitions(),
            $this->articles(),
        );

        $xml = $this->render($urls);

        return response($xml, 200, ['Content-Type' => 'application/xml; charset=UTF-8']);
    }

    private function staticPages(): array
    {
        return Page::query()
            ->where('is_active', true)
            ->where('type', '!=', PageType::Home)
            ->with('translations')
            ->get()
            ->map(function (Page $page) {
                $slug = $page->translations->firstWhere('locale', \App\Enums\Locale::Az)?->slug
                    ?? $page->translations->first()?->slug;

                return $slug ? ['loc' => SeoText::absoluteUrl("/{$slug}"), 'lastmod' => $page->updated_at] : null;
            })
            ->filter()
            ->values()
            ->all();
    }

    private function artworks(): array
    {
        return Artwork::query()->where('is_active', true)->get()
            ->map(fn (Artwork $a) => ['loc' => SeoText::absoluteUrl("/artworks/{$a->inventory_code}"), 'lastmod' => $a->updated_at])
            ->all();
    }

    private function artists(): array
    {
        return Artist::query()->where('is_active', true)->with('translations')->get()
            ->map(function (Artist $artist) {
                $slug = $artist->translations->firstWhere('locale', \App\Enums\Locale::Az)?->slug
                    ?? $artist->translations->first()?->slug;

                return $slug ? ['loc' => SeoText::absoluteUrl("/artists/{$slug}"), 'lastmod' => $artist->updated_at] : null;
            })
            ->filter()->values()->all();
    }

    private function exhibitions(): array
    {
        return Exhibition::query()->where('is_active', true)->with('translations')->get()
            ->map(function (Exhibition $exhibition) {
                $slug = $exhibition->translations->firstWhere('locale', \App\Enums\Locale::Az)?->slug
                    ?? $exhibition->translations->first()?->slug;

                return $slug ? ['loc' => SeoText::absoluteUrl("/exhibitions/{$slug}"), 'lastmod' => $exhibition->updated_at] : null;
            })
            ->filter()->values()->all();
    }

    private function articles(): array
    {
        return Article::query()
            ->where('status', ArticleStatus::Published)->where('is_active', true)
            ->whereNotNull('published_at')->where('published_at', '<=', now())
            ->with('translations')
            ->get()
            ->map(function (Article $article) {
                $slug = $article->translations->firstWhere('locale', \App\Enums\Locale::Az)?->slug
                    ?? $article->translations->first()?->slug;

                return $slug ? ['loc' => SeoText::absoluteUrl("/articles/{$slug}"), 'lastmod' => $article->updated_at] : null;
            })
            ->filter()->values()->all();
    }

    private function render(array $urls): string
    {
        $xml = ['<?xml version="1.0" encoding="UTF-8"?>', '<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">'];

        foreach ($urls as $url) {
            $xml[] = '  <url>';
            $xml[] = '    <loc>'.htmlspecialchars($url['loc'], ENT_XML1).'</loc>';
            if ($url['lastmod']) {
                $xml[] = '    <lastmod>'.$url['lastmod']->toAtomString().'</lastmod>';
            }
            $xml[] = '  </url>';
        }

        $xml[] = '</urlset>';

        return implode("\n", $xml);
    }
}

// resources/js/public/lib/usePageMeta.js
import { useEffect } from 'react';

function upsertMetaByName(name, content) {
    let tag = document.querySelector(`meta[name="${name}"]`);

    if (!content) {
        tag?.remove();

        return;
    }

    if (!tag) {
        tag = document.createElement('meta');
        tag.setAttribute('name', name);
        document.head.appendChild(tag);
    }

    tag.setAttribute('content', content);
}

function upsertCanonical() {
    let tag = document.querySelector('link[rel="canonical"]');

    if (!tag) {
        tag = document.createElement('link');
        tag.setAttribute('rel', 'canonical');
        document.head.appendChild(tag);
    }

    tag.setAttribute('href', `${window.location.origin}${window.location.pathname}`);
}

export function usePageMeta({ title, description, noIndex = false } = {}) {
    useEffect(() => {
        if (title) {
            document.title = title;
        }

        upsertMetaByName('description', description || null);
        upsertMetaByName('robots', noIndex ? 'noindex, follow' : null);
        upsertCanonical();
    }, [title, description, noIndex]);
}

- [ ] **Step 1: Write the documentation**

Create `docs/superpowers/specs/2026-09-18-phase-11-seo-implementation-notes.md` covering, in the same practical, verified-against-code style as the existing `work-files/art-niyyetli-phase-09-frontend-api-guide.md`:

1. **What was built** — the `PublicPageSeoResolver` (server-side, `app/Services/Seo/`), the `usePageMeta` client hook, `robots.txt`/`sitemap.xml`, and the `SeoMetadata` override wiring — one short paragraph each, with exact file paths.
2. **Per-page-type metadata rules** — a table listing, for each of the 11 routes, exactly which entity field supplies the title/description, which JSON-LD types (if any) are emitted, and the indexability rule — this is effectively "Architectural decisions this plan makes," §1–9 above, copied into a developer-facing reference rather than a plan-only note.
3. **Known, accepted limitations** (do not omit any of these — each is a real, verified constraint of the current architecture, not a bug):
   - Server-rendered metadata always defaults to `az` unless the request URL includes `?locale=en`; a returning visitor's `localStorage`-persisted locale preference cannot be read by the server on first load. Real per-request locale detection would require a cookie-based mechanism, which is an explicit non-goal of this phase.
   - `SeoLabels` (`app/Support/Seo/SeoLabels.php`) duplicates four strings from `resources/js/public/i18n/dictionary.js`'s `nav.*` keys, because there is no shared-code layer between the PHP backend and the JS frontend. If the dictionary's nav labels ever change, `SeoLabels` must be updated to match, or the server-rendered `<title>` for list pages will disagree with the client-rendered `<h1>`.
   - There is currently no admin UI for writing `SeoMetadata` override rows — an operator can currently only populate them via `php artisan tinker`. Reading/consuming them is fully wired up and tested; a future phase could add an admin screen for editing them without any further backend change.
   - Catalogue/exhibitions/articles filter and pagination state is not reflected in the URL today (verified: `CataloguePage.jsx`, `ExhibitionsPage.jsx`, `ArticlesPage.jsx` all keep this in local `useState`), so there is currently exactly one canonical URL for each of these three pages. If a future change starts reflecting filters in the URL, the corresponding `PublicPageSeoResolver` branch and its indexability rule (currently always `index, follow` for these three) must be revisited.
   - Exhibition detail pages get a `BreadcrumbList` only, not an `Event` JSON-LD type — this was reviewed and confirmed as final during Phase 11 planning, not deferred. Add an `Event` type in a future phase only if a concrete, documented schema requirement (e.g. ticketing, structured start/end times surfaced to search results) justifies it; none exists today.
   - `og:type` is `article` only for article details and `website` everywhere else — deliberately never `product`, to avoid needing an unsupported OG namespace declaration.
4. **How to add SEO support for a brand-new public page** — mirroring the existing `work-files/1-public-frontend-developer-handoff.md`'s own "worked example" pattern: add a branch to `PublicPageSeoResolver::resolve()` (mirroring the same route pattern already added to `resources/js/public/lib/useRouter.js`), and call `usePageMeta({...})` in the new page component.
5. **Verification commands** — the exact commands from Task 20, so a future developer can re-verify SEO behavior without re-reading the whole plan.
